# ADR-002: Aplicação web estática publicada em hospedagem gratuita, sem backend

## Status

Accepted

## Date

2026-07-22

## Context

O usuário pretende "subir em algum serviço gratuito". O app é pessoal, consome apenas
arquivos JSON (ADR-001) e precisa de uma home e uma página por destino. Não há dados
sensíveis relevantes nem necessidade de contas de usuário. Offline no celular durante a
viagem foi considerado, mas não foi colocado como requisito essencial da primeira versão.

## Decision

A aplicação é um **site/web app estático** (client-side), sem backend, adequado a
serviços de hospedagem estática gratuitos (ex.: GitHub Pages, Vercel, Netlify,
Cloudflare Pages). Os dados JSON são empacotados/servidos junto com os assets estáticos.
A escolha do framework/stack específico fica para a TechSpec.

## Alternatives Considered

### Alternative 1: App com backend próprio

- **Description**: Servidor de aplicação servindo dados e páginas.
- **Pros**: Permitiria escrita de dados, autenticação, APIs.
- **Cons**: Custo/infra, e a maioria dos tiers gratuitos de backend hiberna ou tem
  limites; desnecessário para dados somente-leitura em JSON.
- **Why rejected**: Contraria ADR-001 (somente-leitura) e o objetivo de hospedagem
  gratuita simples.

### Alternative 2: App mobile nativo

- **Description**: App instalável (iOS/Android).
- **Pros**: Melhor experiência offline no celular.
- **Cons**: Publicação em lojas, build específico, muito além do escopo pessoal atual.
- **Why rejected**: Excessivo para começar; a web responsiva atende o uso no celular.

## Consequences

### Positive

- Publicação gratuita e simples; URL compartilhável.
- Sem servidor para manter; deploy é publicação de arquivos estáticos.

### Negative

- Sem processamento no servidor: tudo é resolvido no cliente a partir dos JSON.
- Conteúdo publicado é público por padrão em hospedagem estática (ver Open Questions
  sobre visibilidade).

### Risks

- Offline pleno no celular durante a viagem não é garantido na v1. Mitigação: manter a
  porta aberta para PWA/cache numa fase futura (registrado como Non-Goal atual, não
  descartado).

## Implementation Notes

Layout responsivo (uso confortável no celular mesmo online). Roteamento client-side por
destino (uma "página" por destino).
